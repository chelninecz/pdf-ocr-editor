# PDF OCR Editor

Принудительное распознавание текста (force-OCR) на отсканированных **чертежах
деталей** (упрощённый китайский + английский), правка распознанного текста в окне
приложения и пересборка нового PDF, в котором исходный чертёж сохраняется, а
изменяются только отредактированные/удалённые слова.

Работает **полностью офлайн на CPU** и устанавливается **без прав администратора**.

## Что делает приложение

1. **Force-OCR** — каждая страница растрируется и распознаётся по изображению.
   Имеющийся в исходном PDF (часто ненадёжный) текстовый слой намеренно игнорируется.
2. **Редактирование** — распознанные строки показываются рамками поверх чертежа.
   Можно править текст, двигать/масштабировать/добавлять рамки или **удалить слово**
   (оно будет затёрто на чертеже). Любое действие отменяемо — **Ctrl+Z** / **Ctrl+Y**
   (на несколько шагов), так что случайное удаление откатывается одной клавишей.
   **Превью** (Ctrl+P) показывает результат экспорта.
3. **Пересборка** — новый файл `*_edited.pdf`, который является **оригиналом
   чертежа без изменений, кроме того, что вы поправили**:
   - **отредактированное** слово: старое слово закрашивается цветом фона, а сверху
     рисуется новый текст (настоящий выделяемый векторный текст со встроенным
     CJK-шрифтом);
   - **удалённое** слово: его область закрашивается (затирается), текст не рисуется;
   - **всё остальное остаётся ровно как в оригинале** — включая корректно
     напечатанный русский/другой текст, который OCR-модель плохо читает. Исходный
     файл никогда не изменяется.

OCR-движок: **модели PP-OCRv5 на ONNXRuntime** через `rapidocr-onnxruntime` —
сильное распознавание упрощённого/традиционного китайского + английского, на CPU,
офлайн. Детекция не зависит от языка, а модель распознавания **переключается на
каждый запуск**: `ch` (китайский + английский, по умолчанию), `eslav`
(русский / кириллица) или `latin`. Движок скрыт за небольшим интерфейсом
`OcrEngine` (`app/ocr/engine.py`), поэтому его целиком можно заменить
(Tesseract/EasyOCR), не трогая остальное приложение. Если моделей v5 нет, движок
откатывается на модели v3 из колеса (wheel).

## Установка (для разработки)

Python 3.10–3.14, на пользователя, без админ-прав:

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
python scripts\fetch_models.py            # PP-OCRv5: детекция + китайский rec + cls
python scripts\fetch_models.py --all      # плюс русский (eslav) + latin rec
```

`fetch_models.py` один раз скачивает ONNX-модели PP-OCRv5 (с проверкой SHA256) в
`app/ocr/models/PP-OCRv5/`; затем они попадают в сборку, и приложение работает
полностью офлайн. Без них приложение откатывается на модели v3 из колеса.

## Запуск

GUI:

```powershell
python -m app.main            # или: python run_app.py drawing.pdf
```

Порядок работы: **Open PDF** → **Run OCR** (F5) → правка рамок → **Preview**
(Ctrl+P) → **Export PDF** (Ctrl+E). **Save session** (Ctrl+S) сохраняет небольшой
`.json` рядом с PDF, чтобы продолжить позже.

Консольный режим (удобно для тестов / пакетной обработки):

```powershell
python -m app.cli ocr      drawing.pdf            # печать распознанных строк
python -m app.cli rebuild  drawing.pdf            # запись drawing_edited.pdf
python -m app.cli rebuild  drawing.pdf --dpi 400 -o out.pdf
```

## Сборка портативного пакета (запуск без админ-прав)

```powershell
.venv\Scripts\pip install pyinstaller
python -m PyInstaller build/pdf-ocr-editor.spec --noconfirm
```

Раздавайте всю папку `dist/PDF-OCR-Editor/`; пользователи запускают двойным кликом
`PDF-OCR-Editor.exe`. Не нужны ни установка Python, ни админ-права, ни интернет —
OCR-модели и встроенный CJK-шрифт лежат внутри сборки.

## Структура

```
app/
  ocr/        интерфейс OcrEngine + реализация RapidOCR (PP-OCR ONNX)
  pdf/        renderer (force-OCR), background (бело/цветной фон + затирание), rebuilder
  model/      Document/Page/TextLine + сохранение/загрузка сессии
  ui/         окно PySide6, масштабируемый холст, рамки, поток OCR, превью
  cli.py      консольный интерфейс
build/        spec для PyInstaller
tests/        быстрые тесты без OCR (background + патч-экспорт)
scripts/      генератор тестового чертежа + загрузчик моделей
```

## Настройка и ограничения

- **DPI** (тулбар, по умолчанию 300) — баланс точность/скорость; поднимите до 400
  для плотных чертежей с тонкими линиями.
- **Порог бело/цветного фона** — в `app/pdf/background.py`
  (`WHITE_MIN_LUMA`, `WHITE_MAX_CHROMA`, `BG_UNIFORM_MAX_STD`).
- **Более красивые CJK-глифы**: положите `NotoSansCJKsc-Regular.otf` в `app/fonts/`
  и задайте `CJK_FONT_FILE` в `app/pdf/rebuilder.py`; иначе используется встроенный
  в PyMuPDF шрифт `china-s`.
- **OCR-модели / язык**: по умолчанию **PP-OCRv5 / ch** (китайский + английский).
  На реальных чертежах часто есть **русский** текст (например, ярлыки энергоэффект-
  ивности EAC) — модель `ch` не читает кириллицу, поэтому переключите селектор
  **Lang** (тулбар) или `--lang eslav` (CLI) и перезапустите OCR для таких страниц;
  детекция общая, меняется только распознавание. `latin` — для документов только на
  латинице.
- Сложные случаи (правьте вручную): вертикальный/повёрнутый CJK, символы GD&T /
  допусков, знак диаметра ⌀. Точные CAD-шрифты не воспроизводятся — цель в том,
  чтобы текст был корректным, читаемым и выделяемым.
- Нужен CPU с поддержкой AVX (любой современный ноутбук).
